# EVM RPC 限流与恢复

2026-09-20 的实盘日志中，Robinhood `eth_blockNumber` 和 `eth_chainId` 连续收到 HTTP 429。WebSocket 仍在接收推送，但 HTTP 账户/LP 快照已经过期约 14 分钟。旧的空仓、价格、收益数字不能证明当前链上状态。Hyperliquid 账户和订单快照正常，不是同一次 RPC 故障。

旧行为会把 429 当普通网络错误，每个请求在 1、2 秒后各重试一次。监控的 LP、成交量查询与策略重新对账各自发起请求；重新创建客户端又失去先前失败信息，形成重复请求。429 可以来自服务商的瞬时额度或其他配额策略，仅凭这段日志不能确定其具体限制。

## 处理方式

- 同一进程内，同端点的所有 EVM RPC 客户端共用发送队列，每次最多一个请求在途，默认发送间隔至少 250 毫秒（合计最多约 4 次/秒）。读取、交易广播、nonce、LP 监控和历史补数都受限制。HTTP/WS 的同端点共用队列；WS 订阅推送、Hyperliquid、Solana Triton 不经过该队列。
- HTTP 429、WS 握手 429 和明确表示频率限制的 JSON-RPC 错误会立即进入共享退避，不再快速重试三次。等待依次为 30、60、120、240、300 秒；服务商 Retry-After（秒数或 HTTP 日期）要求更久时按更长时间等待。单次请求成功不立即清零累计退避，至少观察到 60 秒后的成功才恢复初始级别。
- 冷却期间排队请求也不会发出。策略读取返回 degraded，并按剩余退避时间重新对账；监控的 LP、定时 nonce 查询跳过该端点。客户端重建仍保留退避。到期只允许串行探测，成功后继续按间隔读取，不一次性释放积压请求。
- 近 5 分钟成交量统计和历史补数已移除。LP 每 15 秒检查并复用新鲜确认观察，HL 账户仍为每 30 秒；中文报告仍每 60 秒。现有 WSS 与策略/监控共享读取见 [RPC 请求优化](rpc-observations.md)。
- 未确认交易仍保留原哈希、签名交易与 nonce。广播收到 429 不被分类为可自动重试的读取错误，不换 nonce 重发、不清 pending。已有 LP 工作流与订单继续使用原对账规则。
- 日志显示主/历史 RPC 的剩余退避时间、策略是否处于重新对账阶段，并把过期快照的仓位和策略标为“上次观察”。快照读取成功也不等于策略已恢复；需看 `runtime_health.json` 是否完成一轮新决策。

## 配置与升级

旧配置自动获得默认值，无须修改 `config/local.toml`。如需降低请求速率，可将以下字段加入已有配置表，不要重复创建表：

```toml
[liquidity]
rpc_min_interval_ms = 250 # 默认约 4 次/秒；500 表示约 2 次/秒。允许 1..=5000。

```

这是客户端请求上限，不是服务商承诺的可用额度。间隔过大会拉长观察耗时，超过原有新鲜度/观察超时限制时仍停止决策；不会放宽安全阈值。不同模块对同端点设置不同间隔时，当前进程采用较大的间隔；重启后采用新配置。

本次新增字段从经济参数指纹中排除，旧检查点和旧 rearm 绑定继续有效。升级时保留原配置、state_dir、pending、nonce、NFT 和订单台账，沿用保留状态的重启流程。不要为 429 删除数据、重置第一仓或使用平仓清理脚本。代码更新后重新编译：

```bash
cargo build --release --locked
```

此限流协调只覆盖一个进程内相同端点，不能替其他程序、其他服务器或其他 RPC 地址协调共享的服务商/IP 配额。退出程序会清除内存中的退避时间，反复重启不会解决服务商限制。若持续长时间 429，应核查该节点配额或更换有可用额度且支持必要读写方法的 RPC；仍使用原状态重新对账。

## 本地验证

`tests/rpc_limits.rs` 和限流器单元测试覆盖多个客户端同时读取只发送一次 429 请求、客户端销毁后重建、HTTP/WS 共用退避、Retry-After 秒数与日期、逐步退避与恢复、排队取消、合计发送间隔、不同端点隔离，以及区块范围错误和合约回退不误判限流。`tests/evm_fees.rs` 验证签名广播被限流后保留 pending/nonce，二次调用不产生重复广播；`tests/production.rs` 验证上层恢复循环确实等待并保留原交易；旧指纹回归测试验证升级兼容。

测试服务全部在本机环回地址运行，签名只使用公开固定测试向量。未读取真实私钥、未发送实盘交易、未修改线上状态。本地测试不证明公共节点配额已经恢复。

2026-09-20 验证：221 项全量回归通过；追加的排队超时回归 1 项通过，相关 RPC/广播测试复测通过。`cargo fmt --all -- --check`、`cargo clippy --locked --all-targets -- -D warnings`、`cargo build --release --locked --bin lp-maker` 均通过。排队与网络共用单次 20 秒预算，排队超时也不会让广播变为可自动重试的读取错误。
